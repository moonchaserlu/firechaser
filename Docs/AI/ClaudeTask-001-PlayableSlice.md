# Claude 施工单 001：首个可玩切片

## 目标

依据 `Docs/Design/VerticalSlicePlan.md`，在现有 Unity 工程中完成可运行、可测试的首个灰盒切片。不得扩大策划范围。

## 开工前必读

1. `CLAUDE.md`
2. `Docs/AI/UnityProjectContext.md`
3. `Docs/Design/GameDesignBrief.md`
4. `Docs/Design/VerticalSlicePlan.md`

## 建议实施顺序

### 里程碑 A：工程骨架与玩家

- 创建第一方运行时、编辑器和测试程序集。
- 建立 ScriptableObject 配置类型。
- 实现玩家移动、鼠标地面瞄准、体力、翻滚和固定斜俯视相机。
- 接入现有 Input System actions；若需修改输入资产，通过 Unity Editor/UnityMCP 操作。

验收：可在灰盒平面稳定移动和翻滚；相机不抖动；体力消耗与恢复符合策划。

### 里程碑 B：战斗与敌人

- 实现生命、伤害、死亡的可复用组件。
- 实现基础射击、弹匣和换弹。
- 实现一种 NavMesh 近战敌人：待机/发现/追逐/攻击/死亡。

验收：玩家可击杀敌人；敌人可击杀玩家；无重复伤害或死亡后继续行动。

### 里程碑 C：搜刮与背包

- 实现物品定义、固定掉落表、搜索容器、8 格背包。
- 搜索可因离开范围或受到伤害取消。
- 背包满时阻止加入并提供反馈。

验收：三个容器按配置产出；背包数量准确；边界情况无物品复制或丢失。

### 里程碑 D：撤离、仓库与 HUD

- 实现固定撤离区、3 秒连续停留、成功/失败结算。
- 实现会话内仓库；成功才转移物品，死亡不转移。
- 完成最小 HUD 与重新开始入口。

验收：完整闭环可连续游玩两局，第二局仍能看到第一局撤离所得仓库物品。

### 里程碑 E：灰盒场景与验证

- 通过 Unity Editor/UnityMCP 创建灰盒关卡、NavMesh、出生点、容器、敌人和撤离点。
- 添加 EditMode 测试覆盖背包、体力、弹药、掉落和结算等纯逻辑。
- 添加至少一个 PlayMode 测试或可重复的自动验证，覆盖“拾取 -> 撤离 -> 仓库增加”。
- 检查 Console，修复本任务引入的错误和异常。

## 文件与所有权

- Claude 可修改 `Game/Assets/` 下本任务新增的第一方目录和必要的输入/场景配置。
- 不修改 `Docs/Design/` 中的策划结论；发现冲突时停止扩展并记录问题。
- 不修改 `Library/`、`Temp/`、`Logs/`、`UserSettings/`。
- 不手工编辑 `.unity`、`.prefab`、`.asset` YAML。

## 实施要求

- 建议第一方根目录为 `Game/Assets/Game/`，其下至少区分 `Runtime/`、`Editor/`、`Tests/`、`Data/`、`Prefabs/`、`Scenes/` 和 `UI/`；可根据实际情况精简，但需保持边界明确。
- 优先小型、单职责组件；共享纯逻辑尽量与 MonoBehaviour 解耦以便测试。
- 不为未来多人模式预建网络抽象。
- 不导入新的第三方依赖或美术包。
- 每完成一个里程碑都先确认编译与 Console，再继续下一阶段。
