## 3. 参考优先级与已知问题

外观优先级：

1. 本施工单的物品身份、结构和区分要求。
2. 当前 Icon_<itemId>.png 的主轮廓、配色和辨认点。
3. 角色建模参考图的低多边形风格。
4. AI 生成的 ModelSheet_<itemId>.png，仅用于辅助理解体积。

目前有 19 张图标、17 张生成三视图。短刀 short_knife、燃料包 fuel_pack 缺三视图，均有图标，可以正常建模。不要把缺图当作缺少设计。

生成三视图不是精确工程投影，不能逐像素照描。存在的问题包括：

- 废金属的俯角和碎片遮挡不完全自洽。
- 电池、布料等页面仍有轻微俯角，不保证严格等比例。
- 化学瓶、喷雾的正侧面布条位置可能重复或不一致。
- 数据盘不同视图的宽深比例可能不一致。
- 怀表为展示厚度改成开盖参考，链条和表冠方向需统一。
- 12G、5.56 页是单发；9mm 页是组合。所有弹药先建单发，再复制成组。

处理方式：先建立一个空间上合理的模型，统一宽、高、深、遮挡及部件连接，再从同一个模型渲染正交三视图。表面锈斑不必逐点复刻。不得把参考图直接贴在平面上冒充 3D 模型。

## 4. 统一美术要求

世界永久黑暗，物资来自废墟，旧、磨损、反复修补。大块轮廓和有限折面为主；灰褐布料、炭灰金属，少量锈橙色。少做细碎噪点，优先做外轮廓、材质分区和关键连接结构。

- 保留低多边形折面；只在需要的金属边缘使用少量倒角。
- 暗部要有层次，手枪尤其不能变成一整块纯黑。
- 布料用几何折叠、厚度和大块破边表达，不做布料模拟。
- 磨损主要用颜色、粗糙度和少量缺口表达，不把每个划痕建成几何。
- 发光只用于充电电池的绿灯和数据盘的微弱青灯；普通物品不用自发光补亮。
- 不出现文字、数字、商标、红十字、人物或手。
- 不把预览灯光、地面、相机导出到模型 FBX。

建模与材质默认方案（本任务实施建议，不是既有项目硬性标准）：

- 普通道具约 300–1,500 三角面；复杂组合与手枪约 1,000–3,000。
- 这里按导出时实际三角面统计，弹药组包含所有实例；确有轮廓需要可超出，但记录原因。
- 每件尽量 1–2 个材质槽；瓶液、发光部件或复杂组合最多优先控制在 3 个。
- 共享材质和色板；若用纹理，优先 512 或 1024 图集，不给每件堆多张 4K 贴图。
- Unity 使用 URP 兼容材质；不要依赖无法随 FBX 导出的 Blender 程序化节点。
- 几何负责外形，贴图负责污渍。禁用过度平滑造成的塑料感。
- 本轮无需骨骼、布料模拟、武器内部机构或使用动画。

## 7. 比例、轴向与原点

使用米制，Unity 中 1 单位 = 1 米。以下仅为游戏美术起始比例，不是现实制造尺寸；若现有角色尺度要求调整，整套按一致比例调整并记录。

- 三种电池完全同尺寸，整体高度建议约 0.16 米。
- 燃料包最长边约 0.20 米；布料叠最长边约 0.24 米。
- 瓶、喷雾、罐头高度约 0.10–0.18 米。
- 数据盘最长边约 0.13 米，怀表主体直径约 0.06 米。
- 身份牌最长边约 0.06 米。
- 武器外观比例以现有角色和图标为准，不需要现实制造尺寸。
- 弹药保持三种的相对长短粗细；小物可在展示场景单独放大查看，不能把展示缩放烘焙到导出资产里。

普通道具根原点在底部中心；组合取组合底部中心。独立部件保留合理局部原点，如怀表铰链。武器保持可用的展示根原点，另设 GripAnchor；不要为接入现有角色而改动角色源文件。

Unity 交付根节点 localScale=(1,1,1)，localRotation 为零，Y 向上。视觉正面约定为 +Z；武器方向单独在报告说明。Blender 与 Unity 轴向通过导出校正，先导出一件验证，禁止在最终 Prefab 用 100 倍缩放或临时 90° 旋转掩盖导出问题。

应用镜像、旋转和缩放，避免负缩放。检查法线、穿插、意外开口和浮空部件。薄金属、布尾、牌面要有厚度或明确双面材质方案。

## 8. 执行流程

### 阶段 A：建立基准

1. 记录当前工作区状态和可用工具。
2. 打开图标与三视图，不能只读文件名。
3. 制作燃料包以及三种电池；电池共享壳体与接线柱基础模型。
4. 建立共享布料、金属、锈蚀、黄铜、红壳及发光材质。
5. 导出一个模型到 Unity，检查比例、轴向、材质和正常显示；通过后再批量制作。

### 阶段 B：完成全部模型

1. 按施工表完成第一批，再做第二、三批剩余项。
2. 每件完成后检查主轮廓、厚度、配色和相关物品区分。
3. 若程序化生成，脚本必须保留、可重复运行，且只清理自己命名的集合或输出，不清空用户整个工程。
4. 源文件中按 itemId 分集合；共享材质可复用，弹药单体保留可编辑版本。
5. 所有图形细节都围绕最终观看距离，不用高面数弥补轮廓错误。

### 阶段 C：Unity 交付

1. 导入 FBX，配置 URP 材质，建立 19 个展示 Prefab。
2. Prefab 保持简单：根节点、视觉子节点、必要锚点；不挂新增游戏逻辑。
3. 本次展示不要求刚体或物理碰撞器。后续需要拾取碰撞时再接现有交互，不用复杂 MeshCollider。
4. 创建独立 ItemShowcase 场景，按电池、弹药、材料、消耗品、贵重品、武器分组摆放。
5. 不把展示场景加入正式 Build Settings，不修改既有游戏关卡。
6. Unity 生成和编辑场景、预制体、材质，保留 .meta；不要手工拼接 YAML。
7. 有 Editor 辅助脚本时放在 Editor 目录，重复执行不得生成一堆同名副本。

### 阶段 D：渲染和验收

从最终同一模型输出 TOP、FRONT、RIGHT 三个正交视角，不再用图像生成猜测视图：

- 相机互相垂直，正交投影，视图同一比例。
- TOP 与 FRONT 对齐宽度，FRONT 与 RIGHT 对齐高度。
- 输出 Ortho_<itemId>.png，建议至少 1536×1024，浅灰背景，标签在物品外。
- 武器 FRONT 指完整侧面，TOP 为顶部薄轮廓，RIGHT 为端面；写明轴向。
- 另出一张 Beauty_<itemId>.png：暖色左上光、灰褐炭灰调、斜俯视，武器用侧视。
- 用 #16120F 背景制作全套总览，检查 76px 下主轮廓，28px 下身份区分；22px 作为极限参考。
- 以上渲染保存到 QA 目录，不能覆盖 Game/Assets/Game/Art/Icons 中现有的 19 张图标。

## 9. 验收清单

每件都要核对：

- [ ] 有可编辑源对象、可导入 FBX、材质及展示 Prefab。
- [ ] itemId 和命名正确，无遗漏、误覆盖、丢失材质或贴图。
- [ ] 从任意方向看都有合理体积，侧面不只是贴图平面。
- [ ] 导出尺度、朝向、原点正确；Prefab 根节点无补救性缩放。
- [ ] 无倒面、严重穿插、浮空零件、意外开口。
- [ ] 三种电池同款同尺寸，旧/空/充好状态能分辨。
- [ ] 三种弹药和两组材料对照能分辨：废金属/机械零件，布料/绷带。
- [ ] 燃料包是捆扎布块；怀表无数字；急救喷雾无红十字。
- [ ] 充电电池绿光、数据盘青光强度合适，其余不用发光补亮。
- [ ] 深底上手枪轮廓可见，整套配色和折面风格一致。
- [ ] 新三视图由最终模型渲染，三视图展示的是同一个对象状态。
- [ ] Unity 无新增编译错误、丢失引用、粉色材质或 Missing Script。

测试按改动风险执行：纯美术资产以导入检查、场景预览、Console 和截图为主，不写只验证文件存在的空壳测试。如改了 Editor 逻辑，验证其幂等性及已有数据不被覆盖；若确实碰到运行时代码，说明必要性并运行相关现有测试。

若没有可用 Unity Editor，仍完成 Blender 源文件、FBX、材质贴图及渲染，并把 Unity 验证标为“未执行”。不得把未验证写成通过，也不要为了通过检查虚构截图、日志或测试结果。
