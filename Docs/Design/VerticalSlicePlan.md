# 首个可玩切片策划案 V0.1

## 1. 验证目标

本切片只回答一个问题：玩家在“背包收益增加”和“继续逗留的风险上升”之间，是否会产生明确、可重复的撤离抉择。

体验目标：5–8 分钟完成一局；第一次游玩无需说明即可完成移动、搜刮和撤离；第二局开始能够主动权衡容量、生命和剩余目标。

## 2. 本轮范围

### 必须实现

- 单个灰盒荒野场景，包含出生点、3 个搜索容器、1 种敌人和1个固定撤离区。
- 角色在 XZ 平面移动，鼠标指向地面瞄准，空格翻滚，鼠标左键射击。
- 玩家拥有生命、体力和 8 格背包；本轮不实现饥饿、精神与负重。
- 容器交互需要短暂搜索，完成后产出物品。
- 敌人能够发现、追逐、近战攻击并死亡。
- 玩家进入撤离区并持续停留后结算；携带物品写入局外仓库。
- 玩家死亡则本局物品全部丢失，并可重新开始。
- 最小 HUD：生命、体力、弹药、背包槽位、交互提示、撤离进度和结算结果。

### 明确不做

- 营地自由建造、制作、饥饿、精神、昼夜、天气、幻觉。
- 装备耐久、复杂枪械改装、格子旋转或俄罗斯方块式背包。
- 多敌人种类、Boss、随机地图、剧情、多人与联网。
- 正式美术、音频、存档加密和完整设置菜单。

## 3. 核心循环

`出生 -> 搜索容器/遭遇敌人 -> 获得物资并占用背包 -> 决定继续或撤离 -> 撤离结算/死亡清空 -> 查看仓库 -> 再次出发`

一局至少提供两个决策点：

1. 玩家拿到第一批物资后即可撤离，但收益较低。
2. 最有价值的容器位于敌人附近或更远处，迫使玩家承担生命与弹药风险。

## 4. 初始规则与数值

以下均为可配置初值，不应硬编码在玩法脚本中。

| 项目 | 初值 |
| --- | ---: |
| 玩家生命 | 100 |
| 玩家移动速度 | 5 m/s |
| 翻滚持续时间 | 0.35 s |
| 翻滚速度 | 10 m/s |
| 翻滚体力消耗 | 25 |
| 最大体力 | 100 |
| 体力恢复 | 20/s，停止消耗 0.5 s 后开始 |
| 武器弹匣 | 8 发 |
| 单发伤害 | 25 |
| 射击间隔 | 0.25 s |
| 换弹时间 | 1.4 s |
| 敌人生命 | 75 |
| 敌人伤害 | 20 |
| 敌人攻击间隔 | 1.0 s |
| 敌人警戒半径 | 8 m |
| 搜索时间 | 1.5 s |
| 背包容量 | 8 格 |
| 撤离持续时间 | 3 s，离开区域则重置 |

## 5. 物品与收益

首轮只做三种一格物品：

| 物品 | 用途 | 仓库价值权重 |
| --- | --- | ---: |
| 废金属 | 基础资源 | 1 |
| 罐头 | 生存资源占位 | 2 |
| 旧电池 | 稀有资源 | 4 |

三个容器使用固定但不同的掉落表，保证每局可复现、易测试。背包满时，未拾取物品保留在世界中，并显示“背包已满”。本切片不实现丢弃、堆叠和容器 UI。

## 6. 操作

- `WASD`：移动。
- 鼠标：瞄准地面方向。
- 鼠标左键：射击。
- `R`：换弹。
- `Space`：翻滚。
- `E`：搜索容器或确认交互。
- `Esc`：暂停/退出暂停。

## 7. 状态与失败

- 搜索过程中移动出交互范围或受到伤害，搜索取消。
- 翻滚期间不可射击；是否无敌不在首轮提供，避免掩盖战斗问题。
- 生命降为 0 时进入失败结算，本局背包清空，局外仓库不变。
- 成功撤离时，将背包内容累加到局外仓库，再清空本局背包。
- 本轮仓库只需在当前运行会话中保留；磁盘存档进入下一阶段。

## 8. 灰盒关卡

- 使用约 30×30 米平面，斜俯视固定相机。
- 出生点与撤离点分居两侧。
- 容器 A 位于安全近路；容器 B 位于中央、靠近敌人巡逻区；容器 C 位于远端死角并提供旧电池。
- 使用墙体或箱体形成一条安全绕行路线和一条危险捷径。
- 撤离区应清晰可见，但不能从出生点无风险直达全部资源。

## 9. 架构约束

- 使用 Input System，运行时代码不得依赖 `UnityEditor`。
- 数值和掉落表使用 ScriptableObject 配置。
- 玩法组件采用组合式设计；避免单一 `GameManager` 承担输入、战斗、背包和结算。
- 运行时、编辑器和测试代码分开程序集。
- 场景与资产通过 Unity Editor 或 UnityMCP 创建，不直接手改序列化 YAML。
- 为未来扩展保留接口，但本轮不引入联网层、依赖注入框架或通用事件总线。

## 10. 验收标准

1. 从进入 Play Mode 到成功撤离可完整跑通，且无需 Console 手工命令。
2. 玩家可移动、瞄准、翻滚、射击、换弹、搜索、装包和撤离。
3. 敌人能发现并伤害玩家，玩家能击杀敌人。
4. 背包满、搜索取消、撤离中断、死亡和成功结算均有可见反馈。
5. 成功撤离后仓库数量正确增加；死亡后仓库不增加。
6. Unity Console 无新增编译错误或异常。
7. 核心纯逻辑具有 EditMode 测试；关键闭环至少有一项 PlayMode 验证。
8. 所有关键数值可从配置资产调整。

## 11. 后续门槛

只有当测试者会主动说出“再搜一个还是现在撤”的纠结时，才进入饥饿、昼夜、精神、负重和营地建设。若没有出现该抉择，优先调整地图距离、容器收益、敌人压力和撤离位置，而不是增加新系统。
