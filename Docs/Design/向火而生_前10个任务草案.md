## 故事基础

世界是一片被黑暗笼罩的废土。失去光火庇护的人会逐渐兽化，最终成为怪物。兽化用于叙事解释现有黑暗伤害，不要求新增玩家变形、兽化值或精神系统。

玩家是一名寻火者，刚来到一处废弃庇护所。在这个世界里，死亡已经很常见，不把发现尸体本身作为重大剧情转折。这里的燃料即将耗尽，附近物资点可能还有存货；玩家首先需要维持生存，再逐步追寻圣火。

## 地图落点

- 只使用现有主安全屋（叙事名：庇护所）、厂房及发电机、树林、桥、可进入住宅和仓库。
- Q01 的「补给点」使用庇护所附近现有物资点，不新建补给站建筑，不把过桥后的仓库作为首次取燃料地点。
- Q04 的记录放在庇护所现有桌面或陈设旁。
- Q05 在树林现有可达位置布置旧火堆和笔记；优先复用已有资源。
- Q07 使用当前可进入的住宅，不要求把其他房屋全部改为可进入。
- Q08 使用桥附近现有可行走地面，不堵住桥面和唯一过河通道。
- Q09 使用现有仓库室内陈设附近的可达位置。
- Q10 只完成线索展示和阶段收尾，不要求制作下一张地图或实现地图切换。

## Claude 施工要求

### 1. 接入现有系统

复用现有交互、背包、搜刮、光照、黑暗伤害、火堆、发电机、电池和 HUD。采用最小任务状态管理：未开启、进行中、已完成，按 Q01 至 Q10 顺序推进。目标、交互点引用和文案应可配置，避免在多个脚本中散落硬编码。

任务物资需在对应区域保底可得，不能因随机物资生成导致任务无法完成。Q02 应在出发前提供一块空电池，不额外要求玩家先完成商店购买教程。

### 2. 第二个任务的关键效果

开场庇护所保留炉火附近的小范围安全光，室内电灯关闭。Q01 延续炉火；Q02 安装充电电池后，点亮庇护所室内灯光，并让对应有效安全光范围与视觉一致。

厂房修复后亮灯可保留，但任务必须在玩家返回庇护所安装电池后才完成。不要仅用 UI 提示代替照明变化。

核对当前 `Map01Authority` 电池供电与救援撤离的耦合：任务模式下，Q02 安装电池用于恢复照明，不应提前触发救援或结束这条任务链。保留原有玩法入口，通过明确的任务模式配置隔离，不全局删除旧循环。

### 3. 任务判定与容错

- 玩家提前持有燃料、医疗用品、零件或已修复发电机时，读取当前状态继续推进，不强制重复获得或重复修理。
- 提前阅读的剧情记录应保存已发现状态；任务开启时认可已有发现，不重复奖励。
- Q08 开启时，若指定区域已有玩家建造且仍在燃烧的火堆，可直接认可；保证任务阶段存在可获得的燃料。
- Q01 提交燃料与 Q02 安装电池只扣除一次；失败交互不扣资源。
- Q03 只检查并确认医疗物资，不吞掉玩家后续要用的药品。
- 阅读笔记时沿用现有单人阅读暂停方式（如有），避免玩家在阅读时被黑暗伤害。
- 本轮至少保证同一次游玩内任务状态稳定，重开时一致重置；不擅自扩展为完整永久存档系统。
- 玩家死亡、重开后，任务道具与任务进度不能形成不可恢复的断点。

### 4. 表现范围

使用简洁任务追踪：当前任务名、当前一步目标、完成提示。剧情通过少量可交互记录呈现。无需新增 NPC、配音、过场动画、兽化演出或新敌人类型。

记录中的圣火内容保持「线索与传闻」语气，不在本地图直接宣布玩家已经找到圣火。草案中的记录是新增叙事内容，不应误认为工程已有。

### 5. 实施与验收

先核对 Map01 当前场景和系统，再实现任务数据与状态、任务交互点、照明效果、HUD 和完整任务链。遵循项目约定，不直接手改场景和预制体 YAML，不覆盖其他未提交改动。

验收重点：

1. 能从 Q01 连续完成至 Q10，每一步都有明确目标与反馈。
2. Q01 不要求过桥；后续路线使用实际地图可达路径。
3. Q02 完成后庇护所确实亮灯，安全光判定一致，并且没有提前触发救援结束。
4. 所有必要物资保底可得，提前探索不会卡任务，重复交互不会重复扣除或发奖。
5. Q06 可以绕过敌人完成；Q08 火堆仍遵守原有燃尽规则。
6. 黑暗伤害保持现有规则，不新增兽化数值系统。
7. 编译无新增错误，对任务推进、重复提交、提前完成条件和重开状态做必要验证。
