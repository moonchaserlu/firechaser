# 《向火而生》首个可玩版本计划 V0.1

制定日期：2026-10-19

设计依据：《向火而生：游戏策划总结 V0.3》

版本代号：**光路原型**

## 1. 本版本只回答一个问题

玩家是否会主动观察光源、规划深入与回程路线，并愿意消耗本可带回的燃料来换取安全？

目标局长为 5–8 分钟。第一次试玩可以不懂最优策略，但应在短提示内理解：离开有效光照会受伤、火堆能建立临时安全区、安全屋是返程目标。

以下情况表示核心成立：

1. 玩家至少一次因下一段路太黑而停下观察或改变路线。
2. 玩家会纠结“现在用燃料建火”还是“把燃料带回仓库”。
3. 玩家能复述自己的回程计划，而不是只朝任务箭头直走。
4. 事件或受伤会迫使玩家修改原定路线。
5. 成功与死亡结算都清楚，仓库数量正确。

## 2. 范围

### P0：必须完成

- 一间固定安全屋，以及近郊、外围、深层三档区域。
- 永久黑暗环境；普通美术灯与“有效安全光”严格区分。
- 离光预警、黑暗暴露、持续伤害和清晰 HUD 反馈。
- 一种燃料物品、火堆放置、临时照明范围和燃尽。
- 一种近战怪物、受伤流血、有限血迹与循迹行为。
- 一把手枪；沿用现有移动、射击、搜刮、背包和死亡重开。
- 安全屋返程结算与会话级仓库。
- 两种事件模板，每局随机启用一个事件点。
- 一张可在 5–8 分钟跑完的灰盒地图。

### 明确不做

- 霰弹枪、冲锋枪、步枪和完整近战平衡。
- 饥饿、精神、天气、常规昼夜、复杂治疗与负重。
- 自由营地建设、工作台科技树、NPC 和永久磁盘存档。
- 多人、程序化大地图、Boss、正式剧情和正式美术。
- 手电筒、枪口闪光等移动光源的安全效果。
- 火堆添柴、拆除、跨局保留与复杂配方。
- 无限增援或因血迹直接生成敌人。

## 3. 为本次原型锁定的临时规则

这些数值是可调试的试玩基线，不是正式平衡；必须存入配置，不得散落硬编码。

| 项目 | 原型规则 |
| --- | --- |
| 有效光源 | 仅安全屋光、地图固定安全灯、玩家火堆三类；装饰灯和枪口闪光无效 |
| 安全判定 | 玩家中心处于任一有效光源的玩法半径内即安全；范围重叠不叠加效果 |
| 离光预警 | 离开有效光源后先预警 1.5 秒，预警期不扣血 |
| 黑暗伤害 | 预警结束后每秒 20 点；回到有效光源立即停止并清空暴露计时 |
| 玩家生命 | 沿用 100；满血在纯黑中约 6.5 秒死亡（含预警） |
| 建火资源 | 新增单一物品“燃料包”；建造一座火堆消耗 1 个 |
| 初始燃料 | 每局携带 2 个；近郊保证还能获得至少 2 个，避免随机软锁 |
| 火堆放置 | 按 `Q` 进入预览，鼠标选择地面，左键确认，右键或 `Esc` 取消；确认时才扣材料 |
| 放置限制 | 距玩家不超过 3 米；仅 NavMesh/地面；不得与阻挡体、其他火堆或安全屋核心重叠 |
| 建造耗时 | 1.5 秒；移动、受伤或离开交互范围会取消，材料不扣除 |
| 火堆范围 | 半径 6 米；视觉亮区边缘必须与判定边缘一致 |
| 火堆时长 | 点燃 90 秒，最后 15 秒明显闪烁；本版不能添柴 |
| 火堆归属 | 只存在于本局；结算或死亡后清除 |
| 火堆保护 | 只免除黑暗伤害并遮蔽血迹气味；不治疗、不无敌、不强制驱散已近身敌人 |
| 流血触发 | 近战怪物命中玩家时触发 8 秒流血；重复命中刷新时长，不叠层 |
| 血迹生成 | 流血且玩家移动时每 1 秒生成一处，单个存在 15 秒；全场最多保留 12 处 |
| 血迹吸引 | 未直接发现玩家的怪物可在 12 米内发现血迹，并按旧到新调查；不生成新怪物 |
| 光区恢复 | 玩家处于有效光内不再生成血迹；循迹怪物连续 3 秒无直接视认后放弃血迹调查 |
| 直接追逐 | 光区不强行打断已经看见玩家的追逐，避免把火堆变成无敌点 |
| 背包 | 原型配置固定 8 格；燃料与战利品竞争容量 |
| 返程 | 玩家离开安全屋后返程触发区才启用；回到入口连续停留 2 秒结算，受伤或离开会中断 |
| 事件数量 | 两种事件均实现；每局从合格点位中只启用一个，进入场景时确定且不可重复领取 |
| 阅读暂停 | 单人原型打开事件选择时暂停世界；关闭或完成后恢复 |

安全屋与火堆提供的是“黑暗安全”，不是“战斗安全”。安全屋入口附近不摆放敌人，以避免玩家回家时被贴脸堵门。

## 4. 一局的目标节奏

| 时间 | 玩家经历 | 设计目的 |
| --- | --- | --- |
| 0:00–0:45 | 从安全屋出发，在连续光源中学习交互并取得保底燃料 | 无文字墙地理解“光区安全” |
| 0:45–2:30 | 穿过第一个黑暗间隔，决定是否建火，搜刮外围资源 | 产生第一次燃料取舍 |
| 2:30–4:30 | 遭遇怪物或随机事件；受伤时看到血迹与循迹反馈 | 展示失误如何改变路线 |
| 4:30–6:30 | 观察深层高价值容器，选择继续或返程 | 形成主要风险收益抉择 |
| 6:30–8:00 | 沿已建立的光路返回，或因贪心死亡 | 验证火堆位置和返程记忆 |

## 5. 灰盒地图

地图沿用并重建 `VerticalSlice.unity`，不用新开第二套玩法场景。

- **安全屋**：常亮有效光、玩家出生点、返程入口、仓库结果展示。入口从远处可由暖色光识别。
- **近郊**：两到三个相互衔接的固定光区；放置教程容器与燃料保底，不放高价值物。
- **外围**：两个固定微光岛，中间留一个必须短跑或建火的黑暗间隔；配置普通容器、一个敌人和事件候选点。
- **深层**：一处微光观察点、一处高价值容器、一到两个敌人；回程距离足以让剩余火堆时长产生压力。
- **路线结构**：至少一条消耗燃料的短路，以及一条路程更长但可借固定灯通过的保守路线。

固定灯只负责部分落脚点，不能组成无成本直达深区的完整链。站在每个安全点时，画面里应能看到下一处微光或明确地标。

## 6. 两个原型随机事件

### 事件 A：快熄灭的旧火堆

出现位置：外围现有火盆点。

- **添入 1 个燃料包**：该点变为持续 60 秒的有效光源，并揭示附近普通容器。
- **拆走余料**：获得 1 个燃料包，但该事件点永久熄灭并制造一次中等噪声。
- **离开**：不改变状态，可在本局稍后回来选择。

目的：验证“燃料是收益，也是路线成本”。

### 事件 B：黑暗中的物资车

出现位置：外围与深层交界，不在固定光区内。

- **先建火再搜索**：按正常规则消耗燃料并建立火堆，然后安全搜索高价值掉落。
- **摸黑强搜**：持续 3 秒搜索，不额外消耗物资，但黑暗计时和伤害照常进行，并制造一次小噪声。
- **离开**：不改变状态，可稍后处理。

目的：用同一份奖励比较安全投入和健康风险，不做纯文字抽奖。

两种事件共享同一个选择面板、成本校验和完成状态，不各写一套 UI。

## 7. 在现有工程上的实现方式

| 现有能力 | 处理方式 | 新增/扩展位置建议 |
| --- | --- | --- |
| `Health` | 复用统一伤害入口和死亡事件 | 黑暗系统只调用公开伤害接口 |
| `PlayerCharacter` | 继续作为玩家组件聚合入口 | 引用 `LightExposure`、`BleedingStatus`、`CampfirePlacer` |
| `PlayerInteractor` | 复用交互提示与取消语义 | 事件点实现相同的交互契约 |
| `PlayerInventory` | 复用堆叠、容量和结算 | 新增稳定 ID 的燃料物品及消耗 API；容量配置改为 8 |
| `MeleeEnemy` | 保留现有 NavMesh 状态机和直接警戒 | 增加血迹调查目标，不重写战斗 AI |
| `CombatNoise` | 复用事件造成的噪声 | 事件只发布噪声，不直接操控敌人 |
| `RunSession` | 保留开始、死亡、结算和重开 | 记录已离家状态、运行时火堆与事件清理 |
| `ExtractionZone` | 改为安全屋入口返程区 | 仍使用连续停留与中断规则，文案改为“返回安全屋” |
| `SliceHud` | 复用现有程序化 HUD | 增加光照状态、黑暗倒计时、燃料数、建火和事件面板 |
| `VerticalSliceBuilder` | 继续作为场景真源 | 生成安全屋、三档区域、有效灯、事件点和火堆预制体 |

建议新增的核心类型：

- `SafeLightSource`：有效光源及玩法半径；视觉边界由同一半径驱动。
- `LightRegistry`：登记当前有效光源，避免每帧全场查找。
- `LightExposureModel` / `LightExposure`：纯规则计时 + MonoBehaviour 适配。
- `CampfireConfig`、`Campfire`、`CampfirePlacer`：配置、寿命、预览与放置。
- `BleedingModel` / `BleedingStatus`、`BloodTrailMarker`、`BloodTrailRegistry`。
- `WorldEventDefinition`、`WorldEventPoint`、`WorldEventController`：共享事件状态机。
- `RunMetrics`：只在内存记录试玩数据，不接第三方分析服务。

具体类名可服从现有代码风格，但职责边界必须保留。不要引入依赖注入框架或全局通用事件总线。

## 8. 实施顺序与逐项完成标准

### M0：冻结现有闭环

- 记录当前 EditMode/PlayMode 测试结果与 Console 状态。
- 确认 `VerticalSlice.unity` 能完成移动、射击、搜刮、撤离、死亡和重开。
- 给现有场景保留一个可回退的 Git 提交点。

完成标准：没有新增代码；已知基线问题单独记录，不和光源功能混修。

### M1：有效光照与黑暗伤害

- 实现有效光源契约、注册表、暴露计时和伤害。
- 在安全屋和一个固定灯点接入，HUD 显示安全、预警、受伤三态。
- 禁用场景方向光对“安全判定”的影响；保留最低可读环境光，但不伪装为安全区。

完成标准：边界内不扣血；离开 1.5 秒后稳定扣血；重叠光源、光源失效、玩家死亡/重开均无重复订阅或空引用。

### M2：燃料与火堆

- 新增燃料物品、保底供给、放置预览、取消、扣料和 90 秒寿命。
- 让火堆使用与固定灯相同的有效光源契约。
- HUD 显示燃料数量、可放/不可放和即将熄灭状态。

完成标准：只有成功建造才扣 1 个燃料；障碍内无法放置；火堆熄灭后立即不再保护；重开不残留火堆。

### M3：流血与循迹

- 敌人近战命中触发流血；移动时留下有上限、会过期的血迹。
- 敌人在未直接锁定玩家时可发现并按序调查血迹。
- 有效光内遮蔽气味；不产生增援，不打断敌人的直接视觉追逐。

完成标准：敌人能沿血迹改变调查路线；血迹数量有硬上限；进入光区后局面可在规则规定时间内恢复；无无限刷怪。

### M4：安全屋与三档地图

- 将旧撤离点改造为安全屋入口返程区，加入“离家后才可返程”。
- 重建近郊、外围、深层的光照、敌人和掉落分布。
- 配置短危险路线与长保守路线；深层收益显著高于近郊。

完成标准：从出发到返回的正常局为 5–8 分钟；玩家不能出生即结算；成功带回与死亡丢失仍通过原有仓库验证。

### M5：两个随机事件

- 建立通用事件点、选项、成本校验、单局状态和暂停面板。
- 实现“快熄灭的旧火堆”和“黑暗中的物资车”。
- 每局仅启用一个；随机种子可在测试中固定。

完成标准：资源不足的选项不可选且原因明确；奖励不可重复；关闭未完成事件不会吞物品；事件确实改变光路、生命或资源。

### M6：整局可读性与试玩记录

- 完成安全屋方向提示、光边界、熄灭预警、血迹反馈和结果文案。
- `RunMetrics` 记录：局长、黑暗停留、黑暗伤害、建火数量与位置、燃料收支、最深区域、事件选择、结算结果。
- 连续完成不少于 10 局内部试玩并调数值，不新增系统。

完成标准：无长说明也能完成一局；至少 3 名首次玩家中 2 名能说出光路与燃料的取舍；若失败，优先改地图与数值。

## 9. 自动化验证最低集合

### EditMode

- 暴露计时：预警、伤害、回光重置、光源重叠和失效。
- 火堆寿命：点燃、临界预警、燃尽和取消放置不扣料。
- 流血：刷新而不叠层、血迹生成节流、数量上限与过期。
- 事件：成本校验、一次性完成、固定种子选择和奖励幂等。
- 返程结算：未离家不能结算；成功与死亡的仓库差异。

### PlayMode

1. 出生于安全屋，离光后预警并受伤，回光立即停止。
2. 搜到燃料，建火，穿越黑暗，等待燃尽后该区域重新危险。
3. 敌人击中玩家产生血迹，另一只未警戒敌人调查血迹，进光后停止循迹。
4. 完成一次事件后不能重复领取，重开后按新局重新抽取。
5. 带战利品返回安全屋写入仓库；死亡时本局物品清空且仓库不变。

每个里程碑完成后都必须：等待 Unity 完成编译、读取 Console、运行相关测试、实际进入 Play Mode 走一遍改动路径。

## 10. 试玩记录与通过门槛

每局结束记录以下问题，答案比“好不好玩”更重要：

- 玩家在哪里第一次停下观察光源？
- 第一座火堆放在哪里，为什么？
- 是否有燃料但舍不得用？若没有，燃料成本可能过低。
- 是否进入深层？促成或阻止它的因素是什么？
- 回程时是否主动利用自己先前建立的光路？
- 流血造成的是可理解的压力，还是不明所以的死亡？
- 事件是否改变路线，还是只是顺手领奖？

进入下一版本的门槛：10 局有效试玩中至少 6 局出现明确的建火取舍，至少 5 局出现主动回程规划；严重误判光区边界的局数不超过 1 局。

若未达到，不加入更多武器或生存条，先调整光点间距、燃料供给、火堆时长、深区奖励和提示表现。

## 11. Claude Code 执行约束

1. 严格按 M0 → M6 顺序实施；一次只领取一个里程碑。
2. 每次开始前读取本文件和 `Docs/AI/UnityProjectContext.md`。
3. 先检查现有实现，再扩展；禁止重建已有输入、移动、射击、背包、敌人或结算架构。
4. 不直接编辑 `.unity`、`.prefab`、`.asset` YAML；使用 Unity Editor、UnityMCP 或 `VerticalSliceBuilder`。
5. 所有临时数值进入 ScriptableObject 配置，并附中文 Tooltip 或注释说明其试玩目的。
6. 每个里程碑单独提交；提交信息包含里程碑编号。
7. 交付时报告：修改文件、规则变化、测试结果、Console 状态、手动试玩路径和未解决风险。

### 第一个开发指令

> 执行 M0，不修改玩法。读取 `Docs/AI/UnityProjectContext.md` 与本计划，检查当前分支和工作区，打开 `VerticalSlice.unity`，记录 Unity Console，运行现有 EditMode/PlayMode 测试，并手动走通移动、手枪射击、搜刮、敌人战斗、撤离、死亡与重开。把结果写入 `Docs/QA/BaselineValidation_2026-10-19.md`。若发现失败，只记录可复现步骤、期望与实际结果，不在 M0 中顺手修复。完成后等待确认再进入 M1。

## 12. 暂不锁定的问题

以下问题留到光路原型产生真实数据后再决定：

- 火堆是否可添柴、拆除或跨局保留。
- 普通灯与火堆是否在驱怪、治疗或制作上产生差异。
- 是否加入手电筒及电池消耗。
- 是否保留安全屋之外的特殊撤离点。
- 血迹是否由枪伤、黑暗伤害和环境伤害触发。
- 正式版背包容量、燃料配方、掉落概率和局长。

这些问题不得阻塞首个可玩版本，也不应在 P0 中提前泛化实现。
